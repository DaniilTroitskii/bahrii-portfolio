# Портфолио Евгения Бахрия

Статический сайт-портфолио на четырёх языках: английском (основной), русском, украинском и испанском. Собирается генератором [Eleventy](https://www.11ty.dev/). Бесплатно публикуется на GitHub Pages или Netlify.

- Адреса языковых версий: `/en/`, `/ru/`, `/uk/`, `/es/`.
- Страница проекта: `/ru/work/quiet-hours/`.
- Корень сайта `/` сам открывает нужный язык: сначала язык, выбранный посетителем раньше, потом язык браузера, иначе английский.

---

## 1. Запуск на своём компьютере

Нужен [Node.js](https://nodejs.org/) версии 20 или новее.

```bash
npm install        # один раз: установить зависимости
npm run dev        # запустить сайт на http://localhost:8080 (обновляется сам при сохранении файлов)
npm run build      # собрать готовый сайт в папку _site
```

Остановить `npm run dev` можно клавишами **Ctrl + C**.

## 2. Где что лежит

```
src/
├─ _data/
│  ├─ site.json          email, соцсети, шоурил, портрет, техника
│  ├─ projects.json      проекты с отдельной страницей (фильмы, клипы, реклама)
│  ├─ videos.json        раздел «Видео»: просто ссылки на YouTube / Vimeo
│  ├─ photoCaptions.json подписи к фото (необязательно)
│  ├─ festivals.json     фестивали и показы, не привязанные к одному фильму
│  └─ i18n/
│     ├─ en.json         все тексты интерфейса и биография на английском
│     ├─ ru.json         … на русском
│     ├─ uk.json         … на украинском
│     └─ es.json         … на испанском
├─ assets/
│  ├─ img/               фотографии (кадры, постеры, портрет)
│  │  └─ photos/         ← всё, что лежит здесь, попадает в раздел «Фото»
│  ├─ video/             фоновое видео для первого экрана (необязательно)
│  ├─ resume/            резюме в PDF
│  ├─ css/main.css       оформление
│  └─ js/main.js         плеер, меню, анимации, запоминание языка
├─ home.njk              главная страница (из неё собираются все 4 языка)
└─ project.njk           шаблон страницы проекта
```

Для обычных правок нужны только папки `src/_data/` и `src/assets/img/`. Шаблоны и CSS трогать не придётся.

> **Важно про JSON.** В файлах `.json` все тексты пишутся в двойных кавычках `"..."`, а элементы разделяются запятыми. После последнего элемента запятой быть не должно. Если после правки сайт перестал собираться, почти всегда виновата пропущенная или лишняя запятая или кавычка. Сообщение об ошибке в терминале укажет строку.

## 3. Как добавить новый проект на всех четырёх языках

### Шаг 1. Подготовьте картинки

1. Придумайте короткий адрес проекта (**slug**) латиницей, без пробелов, через дефис. Например, `first-snow`.
2. Создайте папку `src/assets/img/projects/first-snow/`.
3. Положите в неё:
   - `poster.jpg` — кадр для карточки в сетке и превью видео. Формат **16:9**, лучше 1920×1080 или больше.
   - `still-1.jpg`, `still-2.jpg`, … — от 3 до 6 кадров. Формат **16:9** или **2.39:1**, ширина не меньше 1920 px.

Уменьшать фото вручную не нужно. При сборке сайт сам сделает версии разных размеров в форматах WebP и JPEG.

### Шаг 2. Добавьте запись в `src/_data/projects.json`

Файл представляет собой список `[ ... ]` проектов. Скопируйте любой проект целиком: от `{` до `}` вместе с запятой после него. Вставьте копию в нужное место (порядок в файле совпадает с порядком на сайте) и поменяйте значения:

```json
{
  "slug": "first-snow",
  "title": { "original": "First Snow" },
  "year": 2026,
  "format": "short",
  "runtime": 11,
  "aspect": "2.39",
  "role": {
    "en": "Director",
    "ru": "Режиссёр",
    "uk": "Режисер",
    "es": "Dirección"
  },
  "logline": {
    "en": "One or two sentences in English.",
    "ru": "Одно-два предложения на русском.",
    "uk": "Одне-два речення українською.",
    "es": "Una o dos frases en español."
  },
  "video": { "provider": "vimeo", "id": "123456789" },
  "poster": "projects/first-snow/poster.jpg",
  "stills": [
    "projects/first-snow/still-1.jpg",
    "projects/first-snow/still-2.jpg",
    "projects/first-snow/still-3.jpg"
  ],
  "crew": [
    { "role": "director", "name": "self" },
    { "role": "dop", "name": "Jane Doe" },
    { "role": "editor", "name": "John Smith" }
  ],
  "festivals": [
    {
      "year": 2026,
      "name": "Slamdance Film Festival",
      "result": { "en": "Official Selection", "ru": "Официальная программа", "uk": "Офіційна програма", "es": "Selección oficial" }
    }
  ]
}
```

Что означают поля:

| Поле | Что писать |
|---|---|
| `slug` | адрес страницы: `/en/work/first-snow/` |
| `title.original` | название фильма в оригинале. Оно показывается на всех языках. |
| `title.ru` / `uk` / `es` | *(необязательно)* официальное переводное название, если оно есть |
| `format` | одно из значений: `short` (короткий метр), `music_video` (клип), `commercial` (реклама), `documentary` (документальный). Перевод подставится сам. |
| `runtime` | длительность в минутах (число без кавычек). Можно удалить строку целиком. |
| `aspect` | `"2.39"` для широкоэкранного фильма или `"16:9"` |
| `role`, `logline` | ваша роль и логлайн на 4 языках. Если какого-то языка нет, будет показан английский. |
| `video.provider` | `"vimeo"` или `"youtube"` |
| `video.id` | ID видео. Для Vimeo это цифры из адреса `vimeo.com/123456789`. Для YouTube это часть после `v=` в `youtube.com/watch?v=aqz-KE-bpKQ`. |
| `crew[].role` | `director`, `writer`, `dop`, `editor`, `producer`, `sound`, `composer`, `colorist`, `production_designer`, `cast`. Названия должностей переводятся сами. |
| `crew[].name` | имя. Слово `"self"` означает «я»: на каждом языке подставится ваше имя в нужной форме. |
| `festivals` | фестивали этого фильма. Если их нет, оставьте `[]`. Они появятся и на странице проекта, и в общем разделе «Фестивали и награды». |

**Своё описание (alt) для кадра.** Если хотите для конкретного кадра своё описание вместо автоматического «Кадр 2 из фильма…», запишите кадр так:

```json
{ "src": "projects/first-snow/still-2.jpg", "alt": { "en": "Anna at the window", "ru": "Анна у окна", "uk": "Анна біля вікна", "es": "Anna junto a la ventana" } }
```

### Шаг 3. Проверьте

Запустите `npm run dev` и откройте http://localhost:8080. Страница нового проекта появится сразу на всех четырёх языках. Шаблоны менять не нужно.

**Удалить проект:** удалите его блок `{ ... }` из `projects.json` (не забудьте про запятые) и его папку с картинками.

## 3а. Раздел «Видео»: добавить ролик за 30 секунд

Раздел нужен для роликов, которым не нужна отдельная страница: тревел-видео, эксперименты, бэкстейдж, учебные этюды.

Откройте `src/_data/videos.json` и добавьте блок в список:

```json
{
  "url": "https://www.youtube.com/watch?v=XXXXXXXXXXX",
  "title": "Зимний этюд",
  "year": 2025,
  "category": { "en": "Travel film", "ru": "Тревел-видео", "uk": "Тревел-відео", "es": "Vídeo de viaje" }
}
```

- Обязательна только ссылка `url`, её можно просто скопировать из адресной строки. Подходят ссылки `youtube.com/watch?v=…`, `youtu.be/…`, `youtube.com/shorts/…` и `vimeo.com/123456789`.
- Превью подтягивается с YouTube или Vimeo автоматически.
- Если хотите своё превью, положите картинку в `src/assets/img/` и добавьте поле `"poster": "имя-файла.jpg"`.
- `title` можно написать одной строкой (она будет одинаковой на всех языках) или по языкам: `{ "original": "...", "ru": "..." }`.
- `year` и `category` можно не указывать.
- Если список пустой (`[]`), раздел и пункт меню «Видео» исчезнут.

Если ссылка не распознана, в терминале появится предупреждение `[videos] link not recognised`, а ролик будет пропущен.

## 3б. Раздел «Фото»: просто положите файлы в папку

1. Скопируйте фотографии в `src/assets/img/photos/`.
2. Всё. Они появятся на сайте в порядке **имён файлов**. Удобно называть их `01.jpg`, `02.jpg`, `03.jpg`… Чтобы поменять порядок, переименуйте файлы.

Подробности:
- Пропорции могут быть любыми: горизонтальные и вертикальные фото сами складываются «кирпичиками».
- По клику фото открывается на весь экран. Листать можно стрелками на клавиатуре, кнопками или свайпом на телефоне. Закрыть — Esc или крестик.
- Если фото больше 12, остальные прячутся под кнопку «Показать ещё».
- Размер уменьшать не нужно, но и загружать 50-мегабайтные файлы не стоит. Достаточно JPEG шириной 2000–3000 px.
- **Подписи (необязательно)** задаются в `src/_data/photoCaptions.json` по имени файла:
  ```json
  "05.jpg": { "en": "Moab, Utah", "ru": "Моаб, Юта", "uk": "Моаб, Юта", "es": "Moab, Utah" }
  ```
  Подпись показывается в полноэкранном просмотре и служит описанием фото для незрячих посетителей.
- Удалите заглушки `01.jpg`–`09.jpg` из папки, когда добавите свои фото.

## 3в. Эффекты: видоискатель, зерно, фоновое видео

- **Первый экран в виде видоискателя.** Уголки кадра, мигающая точка REC и бегущий таймкод. При загрузке кадр открывается, как шторки-каше. Всё это оформление в CSS, настраивать ничего не нужно.
- **Нумерация разделов 01, 02, 03…** ставится автоматически. Если раздел скрыт, номера пересчитываются.
- **Плёночное зерно** лежит поверх всего сайта. Сделать его сильнее или слабее можно в `src/assets/css/main.css`: найдите `.grain` и поменяйте `opacity` (сейчас `0.045`). Чтобы убрать зерно совсем, удалите строку `<div class="grain" …>` в `src/_includes/base.njk`.
- **Фоновое видео на первом экране (необязательно).** Короткий беззвучный фрагмент (5–15 секунд, MP4, до ~5 МБ) будет крутиться за именем вместо статичного кадра:
  1. Положите файл в `src/assets/video/`, например `hero-loop.mp4`.
  2. В `src/_data/site.json` → `reel` → `"loop": "hero-loop.mp4"`.
  3. Сжать видео можно в DaVinci Resolve (H.264, 1920×1080, 4–6 Мбит/с, без звука) или бесплатной программой HandBrake.

У посетителей, у которых в системе включено «уменьшить движение», анимации, зерно и фоновое видео автоматически отключаются.

## 4. Как править переводы

Все надписи на сайте (меню, кнопки, заголовки, биография) лежат в `src/_data/i18n/`, по одному файлу на язык. Структура у файлов одинаковая, отличается только текст:

```json
"nav": { "work": "Работы", "about": "Обо мне", ... }
```

- Меняйте только текст **справа** от двоеточия. Ключи слева (`"work"`, `"about"`) должны совпадать во всех четырёх файлах.
- `name` — имя в форме для этого языка. Оно используется в заголовке страницы, в метатегах и в шапке.
- `meta.description` — описание для поисковиков и превью ссылок (до 160 символов).
- `about.bio` — список абзацев биографии. Каждый абзац пишется в своих кавычках.
- Фигурные скобки `{title}`, `{n}` — подстановки. Их нужно оставить как есть, например: `"Кадр {n} из фильма «{title}»"`.

Названия камер и программ (они одинаковые на всех языках) лежат в `src/_data/site.json`, раздел `gear`.

## 5. Как заменить заглушки на настоящие материалы

Все заглушки помечены словом **TODO** (в JSON это поле `"_todo"`) или текстом в **[квадратных скобках]**. Найти их все можно поиском по проекту (в VS Code: **Ctrl + Shift + F**, запрос `TODO` или `[`).

| Что | Где | Как заменить |
|---|---|---|
| Email | `site.json` → `email` | впишите адрес без скобок |
| Соцсети | `site.json` → `social` | вставьте ссылки. Если `"url": ""` оставить пустым, пункт не показывается (так сейчас скрыт IMDb). |
| Шоурил | `site.json` → `reel.id` | ID вашего видео на Vimeo; для YouTube поменяйте ещё `provider` на `"youtube"` |
| Кадр на первом экране | `src/assets/img/reel-poster.jpg` | замените файл своим кадром (16:9, ширина от 2400 px), **имя оставьте тем же** |
| Портрет | `src/assets/img/portrait.jpg` | фото 4:5 (например, 1200×1500), имя то же |
| Кадры и постеры проектов | `src/assets/img/projects/<slug>/` | замените файлы, сохранив имена, или поменяйте пути в `projects.json` |
| Видео проектов | `projects.json` → `video.id` | ID с Vimeo/YouTube |
| Раздел «Видео» | `videos.json` | сейчас там открытые фильмы Blender Foundation для примера, замените их своими ссылками |
| Раздел «Фото» | `src/assets/img/photos/` | удалите `01.jpg`–`09.jpg`, положите свои фото |
| Диплом, год, город | `i18n/*.json` → `about.degree`, `about.gradYear`, `about.based` | во всех 4 файлах |
| Роль и слоган | `i18n/*.json` → `hero.role`, `hero.tagline` | во всех 4 файлах |
| Биография | `i18n/*.json` → `about.bio` | во всех 4 файлах |
| Резюме | `src/assets/resume/resume-en.pdf` | положите свой PDF с этим именем |
| Резюме на других языках | `resume-ru.pdf`, `resume-uk.pdf`, `resume-es.pdf` | необязательно: если файла нет, кнопка скачивает английское резюме |
| Адрес сайта | `site.json` → `url` | нужен только для локальной сборки; GitHub Pages и Netlify подставляют адрес сами |

**Советы по фото.** Сохраняйте в JPEG высокого качества, ширина 2000–3000 px. Сайт сам сделает лёгкие версии для телефонов. Если картинка по указанному пути не найдена, на её месте появится серая штриховка, а в терминале — предупреждение `[picture] image not found`.

**Заглушки для новых проектов.** Команда `npm run placeholders` создаёт серые картинки-заглушки для всех проектов из `projects.json`, у которых ещё нет картинок. Существующие файлы она **не перезаписывает**.

## 6. Публикация на GitHub Pages

1. Зарегистрируйтесь на [github.com](https://github.com) и создайте новый репозиторий (**New repository**), например `portfolio`. Галочки «Add README» не ставьте.
2. В папке проекта выполните (подставьте свой логин и имя репозитория):
   ```bash
   git add .
   git commit -m "Первая версия сайта"
   git remote add origin https://github.com/ЛОГИН/portfolio.git
   git push -u origin main
   ```
3. На GitHub откройте репозиторий → **Settings** → **Pages** → в поле **Source** выберите **GitHub Actions**.
4. Откройте вкладку **Actions**. Там запустится сборка «Deploy to GitHub Pages» и займёт 1–2 минуты. Когда появится зелёная галочка, сайт будет доступен по адресу `https://ЛОГИН.github.io/portfolio/`.

Дальше каждый `git push` в ветку `main` автоматически обновляет сайт. Настройки лежат в `.github/workflows/pages.yml`. Путь `/portfolio/` сайт учитывает сам.

> Если назвать репозиторий `ЛОГИН.github.io`, сайт будет открываться прямо по адресу `https://ЛОГИН.github.io/`.

### Свой домен на GitHub Pages

1. Купите домен у любого регистратора (Namecheap, Cloudflare, Porkbun и т.п.).
2. В настройках DNS у регистратора добавьте записи:
   - для основного домена `example.com` — четыре записи **A**: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   - для `www.example.com` — запись **CNAME**, значение `ЛОГИН.github.io`.
3. На GitHub: **Settings** → **Pages** → **Custom domain** → впишите `example.com` → **Save**.
4. Когда проверка DNS пройдёт (от нескольких минут до суток), включите **Enforce HTTPS**.
5. Перезапустите сборку: **Actions** → «Deploy to GitHub Pages» → **Run workflow**. После этого все ссылки, hreflang и превью будут указывать на новый домен.

## 7. Публикация на Netlify

1. Загрузите проект на GitHub (шаги 1–2 из раздела выше).
2. Зайдите на [netlify.com](https://www.netlify.com/) через аккаунт GitHub → **Add new site** → **Import an existing project** → **GitHub** → выберите репозиторий.
3. Настройки подтянутся из `netlify.toml` сами: команда `npm run build`, папка `_site`. Нажмите **Deploy**.
4. Через минуту сайт будет доступен по адресу вида `https://имя.netlify.app`. Имя можно поменять: **Site configuration** → **Change site name**.

Каждый `git push` обновляет сайт автоматически.

> Если используете Netlify, файл `.github/workflows/pages.yml` можно удалить, чтобы сайт не собирался дважды.

### Свой домен на Netlify

1. **Domain management** → **Add a domain** → впишите `example.com`.
2. Netlify покажет, какие DNS-записи добавить у регистратора. Проще всего переключить домен на серверы имён Netlify (**Netlify DNS**): тогда всё настроится само.
3. HTTPS-сертификат Netlify выпустит автоматически в течение часа.
4. После подключения домена запустите пересборку: **Deploys** → **Trigger deploy** → **Deploy site**. Тогда ссылки и превью начнут указывать на новый домен.
